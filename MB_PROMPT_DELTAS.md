## 3. [STRUCT] pre_debate stays a USER message via the new `user_preamble` knob (REV 2 — supersedes the rev-1 system-prompt move)

Old repo: `overall_system` + `debater_system` were system-role; `pre_debate` was rendered
as the first user message (`include_pre_debate: true`). Rev 1 had folded `pre_debate`
into the per-speaker system prompt; the user REJECTED that. Rev 2 restores the old
behavior through the new infra knob `user_preamble: {<speaker>: template}` (implementer
E, Rev-2 spec schema): the template is rendered against the speaker's own bindings and
becomes the FIRST user message after the system message in every context for that
speaker. New layout:

- `system.alice` / `system.bob` = `[overall_system, debater_system]`;
  `system.judge` = `[overall_system, judge_system]` (verbatim blocks).
- `user_preamble.alice` / `.bob` = old `pre_debate` (modulo delta 6);
  `user_preamble.judge` = old `pre_debate_judge` (modulo delta 7).
- DC restated a stripped-identical `pre_debate`, so `mb_double_consultancy` inherits
  the debater preambles via `_extends` (asserted equal) and overrides only
  `user_preamble.judge`.

**[STRUCT] message-boundary normalization:** in the old repo `pre_debate` was its own
standalone user message; the new knob renders the preamble as the START of the first
user message (subsequent same-message content follows after a blank line). Same visible
text stream, one fewer message boundary — same normalization class as delta 5's.

## 5. [STRUCT + finding + flag] Attribution blocks PORTED via the new `attribution` knob (REV 2 — supersedes the rev-1 drop)

Rev 1 dropped the old attribution wording for the hard-coded `"{name} said:"`
convention; the user REVERSED that. Rev 2 ports the old wording through the new infra
knob `attribution: {<reader>: {<author>: template}}` (implementer E, Rev-2 spec
schema): when <reader> sees a speech by <author>, the template is rendered against the
READER's bindings and the speech text is appended after a blank line; reader/author
pairs absent from the map fall back to the hard-coded `"{name} said:\n{text}"`.

MB usage (all templates verbatim from the old debate entry; the old DC entry defined
none of these stanzas, so DC inherits them exactly as it did in the old file):

- `attribution.judge.alice` = old `pre_debater_a_speech_judge`:
  "This is what <NAME> said during their speech." (judge bindings: NAME = Debater_A).
- `attribution.judge.bob` = old `pre_debater_b_speech_judge`:
  "This is what <OPPONENT_NAME> said during their speech." (OPPONENT_NAME = Debater_B).
- `attribution.alice.bob` and `attribution.bob.alice` = old `pre_opponent_speech`
  (each debater reading the other; the reader's OPPONENT_NAME is the author):

  > `<br>`
  >
  > This is what the opposing debater, <OPPONENT_NAME>, said during their most recent speech.
  >
  > `<br>`

**`<br>` finding (required verification):** the old parser performed NO transformation
of `<br>`. `PromptParser.parse` substitutes only `<UPPERCASE-FIELD>` placeholders drawn
from `PromptConfig` fields (`prompts/parser.py:495-506`); `<br>` is lowercase and not a
field, and no code anywhere in the old repo replaces or strips it (repo-wide grep).
The literal text `<br>` therefore reached the model verbatim, and the new templates
keep the literal `<br>` lines so the rendered output matches.

**[STRUCT] message-boundary normalization:** in the old repo the attribution stanza was
its OWN user message immediately followed by the speech as a SEPARATE user message
(only consecutive SYSTEM messages were consolidated — `transcript.py:99-110`,
`openai_model.py generate_llm_input_from_model_inputs`). The new knob emits ONE
message: `template + blank line + speech`. Same visible text stream, one fewer message
boundary; recorded as a forced normalization of the new schema.

**[DROP + FLAGGED FOR USER REVIEW] `pre_previous_speech` is inapplicable:** the old
own-speech reintroduction stanza

> `<br>`
>
> This is what you, <NAME>, said during your previous speech.
>
> `<br>`

cannot be ported: in the new infra a speaker's own prior speeches render natively as
ASSISTANT turns in its own conversation and are never reintroduced as user-message
text, so there is no render site for this template. The old debaters DID see this
wrapper around their own previous speech (rendered as a user-role block); the new
debaters instead see their own speech as a plain assistant turn. This is a rendering
difference vs the old arm — flagged for user review.

## 13. [TOPO] Debate sequencing finding (required verification) and topology choice

Verified against `$OLD/debate/speech_format.py:252-296` + `$OLD/debate/turn_plan.py`:

- The MB debate arm ran `debate_mode: dual_proposer_debate` (non-PC) and never set
  `sequential_turns`, whose default is `False` (`experiments/experiment_config.py:709`).
- Non-PC rounds get `second_sees_first = sequential_turns and not last`
  (`turn_plan.py:300-306`, same in `for_debate` :429) — so `second_sees_first` was
  **False for EVERY round**.
- `speech_format.py:290-294`: with `sees_opponent(...)` False, each debater renders its
  OWN same-round speech before the opponent's, i.e. generates blind to the opponent's
  same-round speech; prior-round speeches (both sides) are always in context.

**Finding: the second opener did NOT see the first opening, and the second rebuttal did
NOT see the first rebuttal — both rounds were mutually blind (simultaneous); each
rebuttal saw both openings.**

Resulting topology (per the spec's contingency, NOT the 4-alternating-turns default):
two co-located turns then the judge turn —
`[alice: pre_opening_speech | bob: pre_opening_speech]`,
`[alice: pre_speech | bob: pre_speech]`,
`[judge: deliberation (private), post_round_judge_without_reasoning (decision)]`.
Same-turn co-occupancy gives exactly the old blindness; the judge's flat view is
A-opening, B-opening, A-rebuttal, B-rebuttal — the same interleave the old judge saw.
